## Why

当前要跑通的是从上传 PDF 到拿到带来源回答的流程。只想看 PDF 怎么打开，就要穿过上传进度线程、入库阶段包装和解析分发；这些跳转增加了理解和排查成本。

## What Changes

- 把文件识别、解析、切块、向量化、写入和激活按执行顺序放进一个入库入口。从上传处理函数进入该入口，再点进 PDF 分支就能看到打开文件的代码。
- **BREAKING**：`POST /api/docs` 继续接受多文件表单，处理完毕后一次返回 JSON，按输入顺序提供每个文件的成功结果或具体错误。移除上传 SSE 事件、进度回调和用于传递这些事件的线程与队列。
- 上传页面等待期间显示“正在导入”，结束后展示逐文件结果、刷新文档列表。用户可以随即就导入的内容提问并查看来源。

## Impact

涉及上传路由、入库与解析模块、静态上传界面、相关测试及 README 中的接口说明。使用旧上传事件的客户端需要随服务一起切换到 JSON。问答继续使用自己的 SSE 接口；已有 MySQL 登记记录和 Milvus 文档可直接使用。
