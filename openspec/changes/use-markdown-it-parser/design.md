## Context

入库入口调用 `parse_markdown(name, content)` 得到 `ParsedDocument`。分块器读取有序片段的 `kind`、`text` 和 `heading_path`，据此组织父块并生成引用位置。PDF 通过 PyMuPDF 得到同一种文档结构。两条路径在分块前汇合。

## Goals / Non-Goals

把 Markdown 块边界识别交给成熟库。继续通过现有解析函数交付文件名、逻辑页数、片段及字符数，以便直接验证解析结果如何进入分块与来源引用。PDF 解析、父子块切分策略和持久化格式属于已有流程。

## Decisions

1. **直接调用块解析 API。** 把 `markdown-it-py` 列为运行依赖并更新锁文件，使用 `MarkdownIt("commonmark").enable("table").parse(text)`。继续给现有正则补规则会重复处理围栏长度、容器嵌套和标题优先级。渲染成 HTML 再提取文字则会丢掉代码围栏和表格的原始写法。
2. **以顶层块为输出单位。** 按库标注的起止行从统一换行后的原文取片段。列表、引用、表格各由最外层块一次输出，包含内部内容及其 Markdown 标记。围栏代码和缩进代码映射为代码片段。块级 HTML 可作为普通段落保留原文。水平分隔线只充当边界。逐个输出嵌套节点会让同一段文字被多次向量化。
3. **只让文档层级的标题更新章节路径。** 用标题节点给出的级别和标题内容更新路径，输出带深度的标题片段。同级替换、回到浅层时截断、跳级时只记录实际存在的标题。标题片段保留原文，下划线式标题包含其标记行。容器和代码中的文字随所属块保留。正文继承最近的章节路径。
4. **沿用输入与统计约定。** 按现有策略解码 UTF-8 和规范化换行，以实际输出片段的文本长度之和计算字符数；Markdown 逻辑页数为 1。由现有分块器消费这些片段，以保留从解析到检索的调用路径。

## Risks / Trade-offs

- 有些旧文档用任意两侧带竖线的文本模拟表格 → 按表头分隔行识别表格，并用普通段落保留原文，验收时同时断言这两类文本。
- 引用块现在保留原文引用符号，新标题归属也可能改变分块与字符统计 → 用一份包含引用、示例代码和正文的样例核对实际片段与下游引用。

## Migration Plan

随解析器发布运行依赖和锁文件。新上传及重传的 Markdown 使用新规则。历史文档在需要修正引用时按原文件重新上传。若需回退，恢复解析模块和依赖版本；需要恢复旧片段的文档可再次导入。
