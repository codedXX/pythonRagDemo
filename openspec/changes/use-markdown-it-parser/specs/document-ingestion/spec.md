## ADDED Requirements

### Requirement: Markdown block structure and section attribution

系统 SHALL 按 CommonMark 块语法和管道表格扩展识别 Markdown 文档结构。供分块使用的片段 MUST 遵循原文顺序并携带所在章节的真实标题路径。列表、引用、代码块和表格中的内容 MUST 在解析结果中各收录一次。

#### Scenario: 两种标题写法形成同一条章节路径

- **WHEN** 文档以“安装指南”加下一行 `===` 作为一级标题，随后出现 `## 环境要求` 及其正文，再出现同级标题 `## 配置` 及其正文
- **THEN** 两段正文的章节路径依次为“安装指南 > 环境要求”和“安装指南 > 配置”，检索到后一段时引用指向“安装指南 > 配置”

#### Scenario: 长围栏保留完整代码示例

- **WHEN** “示例”章节内用四个反引号包起代码，内部含一行三个反引号、一行 `# 假标题` 和空行，结束围栏后还有正文
- **THEN** 从起始到结束围栏的原文形成一个代码片段，后续正文的章节路径仍为“示例”

#### Scenario: 嵌套容器只收录一次

- **WHEN** 在“操作说明”章节上传一个含嵌套列表的引用块，引用内含一行标题，引用结束后接一个独立列表
- **THEN** 解析结果依次包含完整引用片段和独立列表片段，两者均归属“操作说明”，嵌套列表中的每个条目仅在引用片段中出现一次

#### Scenario: 表格和普通管道文本按语法区分

- **WHEN** 正文含有一张具备表头和分隔行、两侧省略竖线的合法管道表格，其后隔一空行出现独立一行 `| 普通文字 |`
- **THEN** 整张表的原文形成一个表格片段，最后一行作为普通段落保留
